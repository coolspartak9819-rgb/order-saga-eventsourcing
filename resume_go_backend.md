## Проекты

### Order Saga & Event Sourcing in Go

GitHub: https://github.com/coolspartak9819-rgb/order-saga-eventsourcing

Сервис обработки заказов для e-commerce сценария на Go. Я сделал проект вокруг Event Sourcing и оркестраторной Saga, чтобы показать работу с состоянием заказа через цепочку доменных событий, а не через прямое обновление строки в БД.

Что реализовано:

- доменный агрегат `Order`, который восстанавливается через `LoadFromHistory`
- события `OrderCreated`, `PaymentAuthorized`, `InventoryReserved`, `OrderCompleted`, `OrderCancelled` и failure-события
- `EventStore` с optimistic concurrency control
- in-memory event store для тестов
- PostgreSQL event store с транзакциями
- outbox-таблица и background worker для публикации событий в NATS JetStream
- idempotency middleware по заголовку `X-Idempotency-Key`
- HTTP API для создания и получения заказа
- gRPC-клиенты для Payment и Inventory сервисов
- standalone gRPC-сервисы `payment-service` и `inventory-service`
- Dockerfile и docker-compose для локального запуска всей системы

В этом проекте я специально собрал несколько вещей, которые часто встречаются в реальной backend-разработке: транзакции, повторяемость запросов, компенсации, публикация событий после commit, межсервисное взаимодействие и восстановление состояния из истории.

Проект показывает, что я умею проектировать backend не только на уровне хендлеров, но и на уровне жизненного цикла данных: событие сохраняется в транзакции, затем попадает в outbox, после commit публикуется в брокер, а состояние заказа можно восстановить из истории.
